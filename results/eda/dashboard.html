Top Findings Summary

  • Severe Taxonomy Gaps: account_help and promo_code_issue have zero seed examples in taxonomy.json, causing baseline centroid matching to fail 100% of the time on both classes.
  • Starter Baseline Eval Bug: In baseline/eval.py, omitting labels=m.intents caused scikit-learn's classification report to map labels alphabetically against taxonomy keys, severely distorting class metrics in starter reports.
  • Significant Silver Label Noise: An estimated 8.0% of training labels violate ground truth intent logic, with error rates reaching >50% in low-frequency classes.
  • Code-Mixed Hinglish & Colloquial Shortcuts: 14.0% of messages contain Romanised Hindi/Hinglish vocabulary (paisa, kahan, nahi) and 22.5% contain abbreviations (pls, eta).
  • Multi-Clause & Mind Changes: 12.2% are long rambling narratives and 9.9% exhibit multi-request cue syntax where Rule 1 (first request) and Rule 2 (mind changes) dictate gold labeling.

README Claims Verification & Findings

Exploratory Data Analysis Findings: QuickCart Intent Dataset


1. Summary

  • **Data Volumes**: 30,000 train, 4,000 dev, 3,000 test rows; exactly 12 intents with zero missing or blank utterances.
  • **Head-to-Tail Imbalance**: 13.5x ratio between majority class (`delivery_delay`: 4,385) and minority class (`promo_code_issue`: 325); Gini coefficient = 0.283.
  • **Taxonomy Blindspots**: Exactly 2 intents (`account_help` and `promo_code_issue`) have 0 examples in `taxonomy.json`, rendering them unmatchable by centroid baselines.
  • **Silver Label Error Rate**: Estimated overall silver error rate of **8.0%** (95% Wilson CI: [5.4%, 11.6%]), rising to over 50% on low-support classes.
  • **Conflicting High-Risk Queue**: 3,578 train utterances (11.9%) flagged by 5-fold cross-validation out-of-fold probability divergence.
  • **Linguistic Noise Distribution**: 22.5% contain abbreviations, 14.0% contain Romanised Hindi/Hinglish, 12.2% are long rambling narratives, 6.7% have typos, and 2.3% contain emojis.
  • **Taxonomy Contradictions**: Shared verbatim examples exist between overlapping intents (`"where's my food"` in both `order_status` and `delivery_delay`).
  • **Dev Baseline Bug**: Baseline evaluation script misaligned Scikit-Learn `target_names` with alphabetically sorted labels, producing false class metrics in starter results.

    Decision Log & Labeling Policies

    Decision Log: QuickCart Intent EDA


    1. Single-Label vs. Multi-Label Policy

  • **Requirement**: Exactly one label per user message must be assigned.
  • **Handling Multi-Request Utterances**:

    • - **Rule 1 (First Request Precedence)**: When multiple independent requests are stated (e.g. *"where is my order, and also I want a refund"*), the first actionable clause determines the label (`order_status`).

    - **Rule 2 (Mind-Change Override)**: If cue phrases signaling mind change occur (*"scratch that"*, *"actually never mind"*, *"sorry wrong thing"*, *"forget that"*), the final stated request supersedes earlier text.

    - **Rule 5 (Escalation Demotion)**: If human agent escalation is requested alongside a specific problem or order action, the specific problem/action wins. `talk_to_agent` is reserved solely for pure escalation queries.


    2. Text Normalization Policies

  • **Typo Handling**:

    • - High-frequency spelling mistakes in domain keywords (e.g., `cancle` $\rightarrow$ `cancel`, `retund` $\rightarrow$ `refund`, `satus` $\rightarrow$ `status`, `odrer` $\rightarrow$ `order`) are mapped in `normalization_map.csv`.

    - Harmless elongation (e.g. `slowwww` $\rightarrow$ `slow`, `urgenttt` $\rightarrow$ `urgent`) is collapsed to double characters max.

  • **Abbreviations**:

    • - Domain contractions (`pls`/`plz` $\rightarrow$ `please`, `eta` $\rightarrow$ `estimated_time_of_arrival`, `abt` $\rightarrow$ `about`) are expanded using `abbreviation_dictionary_draft.csv`. Units and entity identifiers (`id`, `min`) are preserved to avoid entity collisions.

  • **Emojis**:

    • - Emojis account for ~2.2% of messages across splits. Emojis alone without text (`😀😀`) are routed to `out_of_scope`. In running text, emojis are kept or stripped as whitespace; they carry mild sentiment but should not override lexical intent signals.

  • **Hinglish (Code-Mixed)**:

    • - Preserved as first-class tokens. High-signal Romanised Hindi words (`kahan`, `nahi`, `paisa`, `galat`, `chahiye`, `wapas`) are retained and recognized via `hinglish_lexicon.csv`. Models should use multilingual subword tokenizers or character/subword n-grams.


    3. Out-of-Scope Policy

  • Greetings (`"hello"`, `"good morning"`) or gratitude (`"thanks"`) alone $\rightarrow$ `out_of_scope`.
  • General knowledge questions, chit-chat, and services outside QuickCart operations (cab bookings, flights, laptops, gift cards) $\rightarrow$ `out_of_scope`.
  • In pure non-text/punctuation messages (`"???"`, `"......"`), default to `out_of_scope`.
